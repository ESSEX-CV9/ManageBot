# 分管身份组轮替模块

这个模块负责分管身份组的月度留任问询、超时卸任与按空缺公开补员。每个被管理身份组有独立配置，数据保存在 `data/roleRotation.sqlite`。

## 状态流

```text
到达每月配置时间 / 管理员立即发起
  -> 固化当时的非 Bot 成员快照
  -> 在全部通知频道发布共享问询（默认 48 小时）
  -> 截止后保留“继续担任”者，移除“离任”和未回答者
  -> 按 Discord 实时非 Bot 成员数计算空位
  -> 有空位：在全部招募频道发布共享招募
  -> 申请人二次确认，锁内复查资格和实时名额后授予身份组
  -> 招满后关闭所有频道的按钮
```

问询期间新加入目标身份组的人不在本轮成员快照中，因此不会被本轮“未回答自动卸任”误伤。管理员在 Discord 中手动修改身份组后，人数也不会依赖旧数据库计数。

成员成功提交“继续担任”或“不再担任”后，Bot 会在其点击按钮的频道公开发布带用户和身份组标注的确认消息。重复回答等错误仍使用仅本人可见消息。

## 管理命令

所有 `/分管轮替` 子命令都使用核心 `permissionManager`：服务器所有者、Administrator 或其中配置的管理身份组可以执行。

- `创建` / `删除`：维护被轮替身份组。
- `设置规则`：设置人数上限、最低入服天数、每月日期、时间、IANA 时区、问询时长和自动执行开关。
- `添加频道` / `移除频道`：分别维护多个通知频道与招募频道，支持文字/公告频道、论坛/媒体频道，以及公开/私密/公告子区。
  - Discord 的斜杠命令频道选择器可能不展示子区或论坛帖子。此时留空“频道”，把开发者模式下复制的目标 ID 粘贴到“频道或子区id”。
  - 配置普通频道或已有子区/论坛帖子时，消息直接发到其中。
  - 配置论坛或媒体父频道时，每轮问询和招募会各自新建一个帖子；若论坛强制要求 TAG，当前会使用论坛列表中的第一个可用 TAG。
- `添加冲突` / `移除冲突`：维护申请互斥身份组。
- `立即问询` / `立即结算` / `立即招募` / `结束招募`：人工干预当前流程；立即招募会跳过问询，直接按 Discord 实时非 Bot 人数计算空位。
- `查看` / `审计`：查看配置、实时人数、场次和最近操作。
- `设置蛙人` / `清除蛙人`：配置独立的 `/呼唤蛙人` 功能。
- `设置蛙人冷却`：修改每位成员的呼唤间隔，默认 60 秒，可设置为 1-86400 秒。
- `添加蛙人呼叫组` / `移除蛙人呼叫组`：维护多个额外允许使用 `/呼唤蛙人` 的身份组。
- `查看蛙人设置`：查看被呼叫身份组、额外呼叫身份组和当前冷却。

创建配置后的默认值是每月 15 日 09:00、`Asia/Shanghai`、问询 48 小时、最低入服 0 天。日期限制为 1-28，确保每个月一定存在该日期。

## 招募资格与并发

点击“申请担任”时进行资格初检，点击仅本人可见的“确认申请”时再次检查：仍在服务器、非 Bot、满足最低入服时长、没有冲突身份组、尚未持有目标身份组、本轮未成功申请且仍有实时名额。

同一配置的结算与授予操作通过进程内互斥锁串行执行；多个招募频道共享同一个 SQLite 场次和 Discord 实时成员数，单实例部署下不会超发。

每个招募频道、子区或新建论坛帖子首次发布招募面板时会真实 `@here` 一次。后续刷新人数和关闭面板不会重复通知；Bot 必须在对应位置拥有“提及 @everyone、@here 和所有身份组”权限。

招募的二次确认按钮仍然仅申请人可见；确认成功并授予身份组后，Bot 会在申请人点击按钮所在的频道公开宣布结果。资格失败、名额已满等失败信息仅申请人可见。

按钮流程里的仅本人可见失败提示还会尝试通过 DM 发送一份副本，并附上原频道链接，方便在消息密集的频道中查收。用户关闭服务器成员私信时，DM 会静默跳过，频道内的原提示仍然有效。

## Discord 权限

机器人需要查看/发送通知和招募频道消息、嵌入链接、管理身份组，并且机器人身份组必须高于所有被轮替身份组。向子区发送时还需要“在子区发言”；为保证被自动归档的子区下个月仍可使用，建议同时授予“管理子区”。若蛙人身份组不可由普通成员提及，机器人还需要“提及 @everyone、@here 和所有身份组”权限。

Bot 账号可以持有被管理身份组，但不进入问询快照，也不计入容量。

蛙人身份组成员始终可以呼叫自己的身份组，管理员还可以配置多个额外身份组获得呼叫权限。`/呼唤蛙人` 的冷却按“服务器 + 用户”独立记录并持久化，默认每人 60 秒只能成功呼唤一次。Discord 消息发送失败不会消耗本次冷却。

## 调度与恢复

下次计划执行时间持久化为 UTC 时间戳，并用配置的 IANA 时区计算。机器人离线错过时间后会在恢复运行时补执行；场次、回答、消息位置和申请记录都在 SQLite 中，重启不会丢失。默认每 30 秒检查一次，可用 `ROLE_ROTATION_TICK_MS` 调整（最低 5000 毫秒）。
