# 标题与 TAG 规范模块（titleGuard）

管理论坛帖子的**分类信息**：标题里的分类词和帖子挂的 TAG 不能互相矛盾。
检测到问题后先通知作者、给自改时间，到期不改机器人自己动手。管理组全程可覆盖、可还原。

完整设计见 [docs/标题与TAG规范模块设计.md](../../../docs/标题与TAG规范模块设计.md)。

`services/` 里前六个文件是**纯逻辑**：不碰 Discord、不碰数据库，可以脱离机器人单独跑测试。

```bash

```

## 调试台（改词表 / 验证判定，不用连 Discord）

```bash
npm run guard:ui        # 然后打开 http://127.0.0.1:5180
```

三个页签：

| 页签 | 干什么 |
| --- | --- |
| **单条测试** | 粘贴标题（可多行）+ 填 TAG，看引擎怎么切分、命中了哪些词、判了哪些规则、打算怎么改 |
| **批量分析** | 拖入 `/论坛标题 导出` 的 xlsx，全量跑一遍，可按处置/规则/关键词筛选，点任一行看完整判定过程 |
| **LLM 判定** | 填 API Key / 接口地址 / 模型（只存内存，不落盘），连通性自检 |
| **词表设置** | 改分类词 / 黑名单 / 白名单 / 互斥集合 / 分类优先级 / TAG 禁令 / TAG 映射，保存即生效 |

配好 LLM 后，凡是判成「需LLM定性」的条目下面都会出现「发起真实 LLM 判定」按钮，
点了会真调接口，并**按判定结果重算方案和通知**，能直接看到判定前后处置的变化。

单条测试会把引擎内部过程全摊开：

- **切分**：每段标成 前缀标记 / 中部标记 / 后缀标记 / 主体，命中的词在段内高亮
- **token**：标记段切出来的 token，标红的含分类词（删词时删的是整个 token）
- **关键词识别**：包括**落选的候选**和落选原因（被哪个更长的词盖住了）
- **判定结果**：每条规则、涉及哪些词和 TAG、能否直接判还是要 LLM
- **整改方案**：新标题、摘哪些 TAG、补哪些 TAG、保留哪个分类、依据是什么

后台跑的是**机器人同一套引擎代码**，所以这里看到的就是线上行为。唯一差别是不调 LLM——
需要 LLM 定性的会明确标成「需LLM定性」。

词表存在 `tools/seed-dict.json`，界面和离线分析脚本 `analyzeTitles.ts` 读的是同一份。

## 六条规则

| 编号 | 规则 | 需要 LLM |
| --- | --- | --- |
| T1 | 标题命中黑名单词 | 否 |
| T2 | 标记段内出现同一互斥集合的多个分类 | 否 |
| T3 | 标题正文出现同一互斥集合的多个分类 | **是** |
| T4 | 标题正文的分类与 TAG 矛盾 | **是** |
| G1 | 同一互斥集合内挂了多个 TAG | 否 |
| G2 | 标题含某分类的标记 → 禁挂指定 TAG | 视触发词位置 |

## 三个关键实现细节

这三条是可靠性的地基，改代码时别破坏：

1. **匹配绝不跨段边界**（`matcher.ts` 逐段独立匹配）
   否则 `XXXX百合】破坏了美好XXXXX` 会被拼出一个根本不存在的「百合破坏」。

2. **最大覆盖，不是最左最长**（`matcher.ts` 的 `pickMaxCoverage`）
   `纯爱牛头人日记` 用最左最长会先吃掉黑名单词 `纯爱牛`、剩 `头人日记`，
   必须选覆盖更长的 `纯爱` + `牛头人` 才能正确判成分类冲突。

3. **书名号和引号不是标记括号**（`segmenter.ts` 的 `MARKER_BRACKETS`）
   只认 `【】[]〖〗〔〕()`。若把 `《》` 也当标记括号，
   `《真正的橘子味世界不允许百合破坏的存在！》` 整段会变成标记段而被直接改错。

## LLM 的安全阀

`rewriter.ts` 的 `isDeletionOnly` 强制校验：**模型给的新标题只能是原标题删字的结果**。
加上「改后重跑检测」和「长度校验」三条全过才允许自动执行，任何一条不过就转人工。
唯一允许加字的路径是黑名单词的替换目标（`纯爱牛 → NTR`），那来自词典，可控。

LLM 不可用时（没配、被关、网络失败、被内容审核拦），T3/T4 全部挂起转人工，
T1/T2/G1/G2 不受影响照常跑。

**调用姿势会自动降级**：`强制 tool call → 模型自行决定 → JSON 输出`，成功哪个记住哪个。
思考/推理模式的模型通常拒绝强制 `tool_choice`（报 `Thinking mode does not support this tool_choice`），
靠这条降级链兜住。JSON 模式下从回复正文里用括号配对抠出 JSON，能穿过模型的推理文字和 ``` 代码块。
无论走哪种姿势，「新标题只能是原标题删字」这道校验都照跑。

## 配置

**代码里不内置任何词典和互斥集合**，全部由管理组线上维护：

```
/标题规范 词典 添加 / 删除 / 列表 / 导出 / 导入
/标题规范 互斥组 添加 / 移除 / 禁令 / 列表
/标题规范 tag映射 自动生成 / 查看 / 修改
```

LLM 走 `.env` 的 `TITLEGUARD_LLM_*`，其余走 `/标题规范 配置`。

**权限判定**一律用 `core/utils/permissionManager` 的 `checkAdminPermission`。
配置里的「接警身份组」只决定「呼叫管理组」按钮 @ 谁——有权限改和想被 ping 是两回事。

## 上线顺序

1. `/标题规范 扫描 <论坛> 静默:true` —— 只出 Excel 报表，不发通知不改动。
   摸清存量规模、检查误判、把白名单词补齐。
2. 词典定稿。
3. `/标题规范 配置 启用:true 自动整改:true` —— 全套规则一次性生效。

老帖走慢速队列（默认 20 分钟一个）。慢是故意的：老帖发通知会顶帖，
慢速摊平才不会把论坛首页刷成翻出来的老帖。用 `/标题规范 队列 状态` 看进度和预计耗时。
