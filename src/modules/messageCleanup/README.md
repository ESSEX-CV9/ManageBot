# 紧急消息冲水模块

管理组通过 `/冲水 面板` 指定用户、频道范围和截止时间，后台仅删除该用户自己的消息。

服务器本机也可以运行 `npm run console`：使用“内容维护”进入文字 TUI，或选择“本地网页控制台”启动浏览器操作界面。两种控制台都不会登录第二个 Discord Client，只与 Bot 主进程共用 SQLite；网页端可以创建和控制任务、按频道名搜索多个范围、管理索引，并每秒显示当前扫描的主频道/子区、已读页数、已读消息数以及删除和索引进度。Bot 仍需拥有目标频道对应的 Discord 读取、删除与管理子区权限。

本地网页服务默认只监听 `127.0.0.1:3210`，每次启动都会生成新的临时访问密钥并包含在 console 输出的地址中；按 Enter 返回主菜单时服务和密钥立即失效。端口可通过 `MANAGE_CONSOLE_PORT` 修改。网页刷新状态只查询本地 SQLite，不会额外消耗 Discord API。

- 普通文字/公告频道可选择是否递归活动与归档子区。
- 论坛/媒体频道始终递归其活动与归档帖子。
- 当前任务可排除频道、分类、子区或论坛帖子；没有默认保护项。
- 可先在任务页建立全服务器消息索引，并指定最多 25 个频道、分类或论坛作为优先范围；索引仅保存服务器、频道、消息、作者 ID 和时间，不保存消息内容。
- 优先范围会连同其聊天子区或论坛帖子先完成，再继续其余全服范围；建库运行中也可以调整优先范围。
- 索引按频道记录历史覆盖时间；某频道完成后立即可用，刷新索引时只读取上次覆盖时间之后的缺口。
- 首次建库逐频道翻完整历史，每读取一页就立即持久化；支持暂停、继续、取消和进程重启续跑。
- 建库完成后由 `messageCreate` / `messageDelete` 事件实时维护，新冲水任务会立即从索引装入目标消息。
- 每次冲水读取的一页历史会同时把全部作者的消息元数据写入索引，而目标用户的消息进入删除队列；一次 Discord 读取同时完成清理和建库。
- 第一次发起冲水但还没有索引时，会自动建立后台全服索引任务；紧急冲水结束后继续补齐全服范围。
- 没有可用索引时，先用 Discord 服务器消息搜索加速删除，再逐频道翻完整历史做全量核验；搜索结果不会被当成最终数量。
- 已被频道索引完整覆盖的时间范围不再重复读取；未覆盖频道或更晚的截止时间只扫描缺口。
- 两阶段以消息 ID 持久化去重，任务完成后的“最终找到”才是完整数量。
- 扫描器只负责发现消息并写入 SQLite 待删除队列；删除器独立消费，删除接口限流不会在业务流程上阻塞扫描翻页。
- 面板分别显示已发现、待删除、已删除、跳过和失败；只有扫描完成且待删除队列清空后任务才完成。
- 临时网络错误、Discord 429 和 5xx 会按退避时间留在队列中重试，进程重启后继续处理。
- 归档子区/论坛帖会在操作前临时打开，并在删除结束或报错后重新归档。
- 14 天内消息批量删除，旧消息逐条删除。
- 任务、游标和统计保存在 `data/messageCleanup.sqlite`，进程重启后可续跑。

完整历史核验和全服建库共用读取节奏：同一频道默认每 1100ms 最多发起一页（每页 100 条），全局默认每 150ms 发起一页，并默认并行处理 8 个频道。分别可用 `MESSAGE_CLEANUP_HISTORY_PAGE_INTERVAL_MS`、`MESSAGE_CLEANUP_HISTORY_GLOBAL_INTERVAL_MS` 和 `MESSAGE_CLEANUP_HISTORY_CHANNEL_CONCURRENCY` 调整。

机器人在目标范围需要 `View Channel`、`Read Message History`、`Manage Messages`；打开和恢复归档区域、枚举全部归档私密子区还需要 `Manage Threads`。
